# 06 - UI Module: Fragments & Navigation

This document describes the business logic of QuickNovel's UI layer: the single-Activity + Fragments architecture, the AndroidX Navigation graph, the MVVM contract shared by every screen, and the two cross-cutting flows that tie screens together — search fan-out across providers and `loadResult` (open a novel detail page / launch reading & downloading).

All paths are relative to `app/src/main/java/com/lagradost/quicknovel/` unless noted.

---

## 1. Architecture overview: single Activity + Fragments + AndroidX Navigation

The app is a single-Activity application. `MainActivity` (`MainActivity.kt`) hosts:

- A `NavHostFragment` (`R.id.nav_host_fragment`) whose `NavController` drives all screen transitions, using the graph `res/navigation/mobile_navigation.xml`.
- A `BottomNavigationView` (`R.id.nav_view`) bound to the nav graph's top-level destinations.
- A persistent bottom-sheet "preview" popup (`BottomPreviewBinding`) driven by a `ResultViewModel` owned by the Activity (see §6).

### Navigation graph (`res/navigation/mobile_navigation.xml`)

`app:startDestination` is `@+id/navigation_download` (the app opens on the Downloads tab).

Destinations (fragment class ← nav id):

| Nav id | Fragment | Screen |
|--------|----------|--------|
| `navigation_homepage` | `ui.home.HomeFragment` | Browse / provider grid |
| `navigation_search` | `ui.search.SearchFragment` | Global search |
| `navigation_download` | `ui.download.DownloadFragment` | Downloads + bookmark tabs (start destination) |
| `navigation_settings` | `ui.settings.SettingsFragment` | Preferences |
| `navigation_mainpage` | `ui.mainpage.MainPageFragment` | A single provider's main page / browse-by-filter |
| `navigation_history` | `ui.history.HistoryFragment` | Reading history |
| `navigation_results` | `ui.result.ResultFragment` | Novel detail page |

Two global `<action>` elements with typed `<argument>`s drive non-tab navigation:

- `global_to_navigation_results` → `navigation_results`. Args: `url: string`, `apiName: string`, `startAction: integer` (default 0). Used by `loadResult` (§5).
- `global_to_navigation_mainpage` → `navigation_mainpage`. Args: `url: string`, `mainCategory: integer`, `orderBy: integer`, `tag: integer`. Used e.g. from the result page tag chips and from the home browse grid.

Note: arguments are passed as raw `Bundle`s built by helper factory functions (`ResultFragment.newInstance`, `MainPageFragment.newInstance`) rather than via generated SafeArgs classes.

### Bottom-nav behavior (`MainActivity.onNavDestinationSelected`)

`MainActivity` installs its own `OnItemSelectedListener` (not the stock `NavigationUI` binding). `onNavDestinationSelected(item, navController)` builds `NavOptions` with `setLaunchSingleTop(true)`, `setRestoreState(true)`, custom enter/exit/pop anims, and (for primary items) `setPopUpTo(graph.findStartDestination().id, inclusive=false, saveState=true)`. This gives multi-tab state saving/restoring. `addOnDestinationChangedListener` → `updateNavBar(destination)` toggles `navView.isVisible` so the bottom bar shows only on the six top-level destinations and is hidden on `navigation_results`.

### View Binding

Every fragment uses **View Binding** (not Data Binding, not `findViewById` outside of `SearchView` internals). The pattern is centralized in `ui/BaseFragment.kt`:

- `BaseFragment<T : ViewBinding>` takes a `BindingCreator<T>` — either `BindingCreator.Inflate(Binding::inflate)` (the common case, e.g. `HomeFragment : BaseFragment<FragmentHomeBinding>(BindingCreator.Inflate(FragmentHomeBinding::inflate))`) or `BindingCreator.Bind` (for differing TV/phone layouts via `pickLayout()`).
- `onCreateView` delegates to `createBinding`, which wraps inflation in try/catch, shows a toast + `logError` on failure, and stores the nullable `_binding`. Subclasses override `onBindingCreated(binding, savedInstanceState)` instead of `onViewCreated` (which is `final`).
- `onDestroyView` nulls `_binding` to avoid leaks; all observers therefore must tolerate `binding == null`.
- `fixLayout(view)` is the idempotent hook for system-bar padding and (in grid screens) span-count selection on rotation; it is re-invoked from `onConfigurationChanged`.
- Sibling base classes: `BaseDialogFragment`, `BaseBottomSheetDialogFragment`, `BasePreferenceFragmentCompat`.

A custom binding-aware `observe`/`observeNullable` extension (in `mvvm/ArchComponentExt.kt`) attaches the `LiveData` observer to the binding **root view's** lifecycle (`root.doOnAttach { ... findViewTreeLifecycleOwner() }`) rather than the Fragment, so callbacks don't fire while the view is detached/backgrounded.

## 2. The MVVM pattern (`mvvm/ArchComponentExt.kt`)

Every screen follows ViewModel → `LiveData` → Fragment-observes. The core contract lives in `mvvm/ArchComponentExt.kt` (the `mvvm/` package contains only this single file).

### `Resource<T>` — the load-state wrapper

```kotlin
sealed class Resource<out T> {
    data class Success<out T>(val value: T) : Resource<T>()
    data class Failure(val cause: Throwable?, val errorString: String) : Resource<Nothing>()
    data class Loading(val url: String? = null) : Resource<Nothing>()
}
```

ViewModels post `Resource<…>` into `MutableLiveData`; fragments `when`-branch over `Success` / `Loading` / `Failure` to toggle progress bars, error views and content. Helpers: `Resource.map`, `letInner`.

### `safeApiCall` — turn a throwing suspend call into a `Resource`

```kotlin
suspend fun <T> safeApiCall(apiCall: suspend () -> T): Resource<T> =
    withContext(Dispatchers.IO) {
        try { Resource.Success(apiCall.invoke()) }
        catch (t: Throwable) { logError(t); throwableToResource(t) }
    }
```

Runs on `Dispatchers.IO`, logs, and maps the throwable to a user-readable `Resource.Failure` via `throwableToResource` → `throwableToMessage` (which special-cases `SocketTimeoutException`, `UnknownHostException`/`ConnectException`, `SSLHandshakeException`, `NullPointerException` in provider files → "Site might have updated or added Cloudflare/DDOS protection", etc.). This is the boundary used by `APIRepository`/`MainPageRepository` so providers can just throw.

### Error logging

`logError(throwable)` prints a delimited block to Logcat (tag `ApiError`) and `printStackTrace()`. Sibling safety wrappers: `safe { }` (sync, returns null on throw), `safeAsync { }`, and `CoroutineScope.launchSafe { }` (launches a coroutine whose body is wrapped in try/`logError`). ViewModels heavily use `viewModelScope.launchSafe { }` and `Coroutines.ioSafe { }`.

### `Event<T>` — one-shot / multicast UI events (`util/Event.kt`)

```kotlin
class Event<T> {
    private val observers = mutableSetOf<(T) -> Unit>()
    operator fun plusAssign(observer: (T) -> Unit) { observers.add(observer) }
    operator fun minusAssign(observer: (T) -> Unit) { observers.remove(observer) }
    operator fun invoke(value: T) { observers.forEach { it(value) } }
}
```

A lightweight observer registry used for transient signals that should not be replayed like `LiveData` would. Example: `SearchFragment.configEvent: Event<Int>` broadcasts the current grid span count to any open expanded-list bottom sheet; listeners are added with `configEvent += spanListener` and removed on dismiss with `configEvent -= spanListener`.

### Debug assertions

`debugException { }`, `debugWarning { }`, `debugAssert(…)` throw/log only in `BuildConfig.DEBUG` (e.g. `ResultFragment` asserts that a review list never reaches `Resource.Failure`).

## 3. Screen-by-screen logic

### Home — `ui/home/HomeFragment` + `HomeViewModel`

The browse/provider grid. `HomeViewModel.homeApis: LiveData<List<MainAPI>>` is a lazily-built `MutableLiveData` filtering `Apis.apis` down to providers where `api.hasMainPage` **and** the provider's language is enabled (`getApiProviderLangSettings()`). `HomeFragment.onBindingCreated` wires a `BrowseAdapter` into `homeBrowselist` and observes `homeApis`. `fixLayout` sets span count (3 portrait / 6 landscape). Tapping a provider navigates to `navigation_mainpage`.

### Search — `ui/search/SearchFragment` + `SearchViewModel`

Global cross-provider search (see §4 for fan-out). The fragment owns **two** view models: `SearchViewModel` (search) and `HomeViewModel` (the browse grid shown when no search is active).

It maintains three display modes via two `LiveData`s:
- `viewModel.searchResponse: Resource<ArrayList<SearchResponse>>?` → the merged/"all" flat list shown in `searchAllRecycler` (used when *not* in advanced mode).
- `viewModel.currentSearch: ArrayList<OnGoingSearch>?` → per-provider grouped results shown in `searchMasterRecycler` (advanced mode; each `OnGoingSearch` is `apiName` + its own `Resource`).
- When `searchResponse == null`, the `homeBrowselist` browse grid is shown instead.

`advanced_search` preference picks between the flat and grouped recyclers. The `SearchView.OnQueryTextListener` calls `viewModel.search(query)` on submit and `viewModel.clearSearch()` when the text is emptied. `searchFilter` opens `SettingsFragment.showSearchProviders`. The companion `loadHomepageList(viewModel, item)` opens a `HomeEpisodesExpandedBinding` bottom sheet listing one `HomePageList` and subscribes to `configEvent` for span updates. `SearchFragment.currentDialog` is a static reference dismissed by `loadResult` before navigating.

### Main page — `ui/mainpage/MainPageFragment` + `MainPageViewModel` + `MainPageRepository`

A single provider's browse page with infinite scroll, filters and an in-page search. `newInstance(apiName, mainCategory, orderBy, tag)` builds the args bundle. `MainPageViewModel.init(apiName, …)` (guarded by `hasInit`) creates a `MainPageRepository(Apis.getApiFromName(apiName))` and loads page 0.

Key state:
- `currentCards: Resource<SearchResponseList>` where `SearchResponseList(items, pages, id)` accumulates results in `infCards` across pages.
- `currentMainCategory` / `currentOrderBy` / `currentTag` (indexes into `api.mainCategories` / `api.orderBys` / `api.tags`) drive filter spinners and reload via `setMainCategory/setOrderBy/setTag` → `load(0, …)`.
- `isInSearch` toggles between filtered browse mode and `search(query)`; `switchToMain()` restores the saved browse `oldResponse`.

`MainPageRepository.loadMainPage(...)` maps the selected filter indices to the provider's `(label, value)` pairs and calls `api.loadMainPage(...)`; `search(query)` calls `api.search(query)`. The fragment's `RecyclerView.OnScrollListener` triggers `viewModel.load(null, …)` for the next page when the user reaches the bottom (and not already loading / searching).

### Result (detail) — `ui/result/ResultFragment` + `ResultViewModel`

The novel detail page and the launch point for reading/downloading — the largest screen. Covered in detail in §5–§6.

### Download — `ui/download/DownloadFragment` + `DownloadViewModel`

The start screen. A `ViewPager2` (`ViewpagerAdapter`) with a `TabLayoutMediator`: tab 0 is Downloads (`R.string.tab_downloads`), the remaining tabs are the bookmark `ReadType`s from `viewModel.readList`. `viewModel.loadAllData(true)` loads everything; `viewModel.pages` drives the pager; `switchPage(position)` persists the current tab (`CURRENT_TAB` under `DOWNLOAD_SETTINGS`). The FAB opens a `SortBottomSheetBinding` sheet with a `SortingMethodAdapter` (different sorting key sets for the downloads tab vs. the reading/bookmark tabs, persisted under `DOWNLOAD_SORTING_METHOD` / `DOWNLOAD_NORMAL_SORTING_METHOD`). A `SwipeRefreshLayout` triggers `viewModel.refresh()` / `refreshReadingProgress()`. `viewModel.refresh` (a `Flow`) updates per-page progress. Search uses `viewModel.search(query)` with fuzzy matching (`FuzzySearch`). This file also declares two shared data classes consumed across the app: `DownloadFragment.DownloadData` (Jackson-serialized persisted model) and `DownloadFragment.DownloadDataLoaded` (runtime, with download state + lazy poster `image`, and `isImported` for epub/pdf imports).

### History — `ui/history/HistoryFragment` + `HistoryViewModel`

Reading history backed by the `HISTORY_FOLDER` key-value store. `HistoryViewModel.updateHistory()` (called from `init`, on `ioSafe`) reads all `ResultCached` entries, sorts by `-cachedTime`, and posts to `cards`. The fragment observes `cards` into a `HistoryAdapter` and shows an empty-state holder. Toolbar overflow → `deleteAllAlert()`. ViewModel actions: `open(card)` → `loadResult(card.source, card.apiName)`; `showMetadata(card)` → `MainActivity.loadPreviewPage(card)`; `stream(card)` → `BookDownloader2.stream(card)`; `delete`/`deleteAlert`.

### Settings — `ui/settings/SettingsFragment`

Extends `PreferenceFragmentCompat` (preference-based, not View Binding for the list itself, though it uses `LogcatBinding` for the logcat dialog). Hosts provider language/enabled selection, backup/restore (`BackupUtils`), updates (`runAutoUpdate`), and the static `showSearchProviders(context)` used by the search screen's filter button. Writes `providersActive` (the active-provider set) which the search fan-out reads.

## 4. Search fan-out across providers (`SearchViewModel.search`)

`SearchViewModel` holds `repos = apis.map { APIRepository(it) }` — one repository per provider. `search(query)`:

1. Ignores queries of length ≤ 1 (calls `clearSearch()`).
2. Cancels any in-flight `ongoingSearchJob` and launches a new one with `Coroutines.ioSafe { }`.
3. Bumps a `@Volatile searchCounter` and captures `localSearchCounter`; this is the stale-result guard — late postings are dropped when `localSearchCounter != searchCounter`.
4. Posts `Resource.Loading()` to `searchResponse` and an empty list to `currentSearch`.
5. Filters `repos` by the active provider set: `providersActive.isEmpty() || providersActive.contains(a.name)`.
6. **Fans out in parallel** using `.amap { ... }` (`util/ParCollections.kt`: `map { async { f(it) } }.map { it.await() }` — concurrent `async` over a `GlobalScope`-derived scope). Each provider's `a.search(query)` (an `APIRepository` returning `Resource<List<SearchResponse>>`) is wrapped in an `OnGoingSearch(a.name, result)` and appended to `currentList`; after each completion the partial `currentSearch` is re-posted so the advanced UI streams in per-provider results as they arrive. `isActive` is checked to bail early on cancellation.
7. After all providers finish, it builds the flat merged list: it takes only the `Resource.Success` sublists and **interleaves** them by index (round-robin across providers) so the most-relevant top hit from each provider floats to the top, then posts `Resource.Success(list)` to `searchResponse`.

`load(card)` / `showMetadata(card)` delegate to `loadResult(...)` and `MainActivity.loadPreviewPage(...)`.

## 5. Opening a novel: the `loadResult` flow

`loadResult` is the single entry point for "open this novel's detail page", defined as companion extensions in `MainActivity.kt`:

```kotlin
fun loadResult(url: String, apiName: String, startAction: Int = 0) =
    (activity as? AppCompatActivity)?.loadResult(url, apiName, startAction)

fun FragmentActivity.loadResult(url: String, apiName: String, startAction: Int = 0) {
    SearchFragment.currentDialog?.dismiss()
    runOnUiThread {
        this.navigate(R.id.global_to_navigation_results,
            ResultFragment.newInstance(url, apiName, startAction))
    }
}
```

`Activity?.navigate(@IdRes, Bundle?)` finds the `NavHostFragment` by `R.id.nav_host_fragment` and calls `navController.navigate(...)`, wrapped in try/`logError`. Callers include `SearchViewModel.load`, `HistoryViewModel.open`, `DownloadViewModel`, and the preview popup's "read more" button.

### ResultFragment → ResultViewModel load

`ResultFragment.onBindingCreated` reads `url` + `apiName` from `savedInstanceState`/`arguments` (throwing `NotImplementedError` if absent), and if `viewModel.loadResponse.value == null` calls `viewModel.initState(apiName, url)`.

`ResultViewModel` has three `initState` overloads, all guarding shared state with a `loadMutex: Mutex`:

- `initState(apiName, url)` — the **network load**. Sets `isGetLoaded = true`, posts `Resource.Loading(url)`, calls `repo?.load(url)` (returns `Resource<LoadResponse>`), and on `Success` stores `load`, computes `loadId = generateId(res, apiName)`, calls `setState(tid)`, and posts the final `Resource<LoadResponse>` (Success/Failure) to `loadResponse`.
- `initState(card: ResultCached)` and `initState(card: DownloadFragment.DownloadDataLoaded)` — **cache/preview loads** (`isGetLoaded = false`) that synthesize a `StreamResponse` from already-known metadata without hitting the network; used by the bottom-sheet preview (§6).

`setState(tid)` sets `loadId`, restores the bookmark `readState` from `RESULT_BOOKMARK_STATE`, records `DOWNLOAD_EPUB_LAST_ACCESS`, caches chapter indexes (`reCacheChapters`), `updateBookmarkData()`, sets `hasLoaded = true`, and seeds download progress via `insertZeroData()`.

`ResultFragment.newState(loadResponse)` renders the three `Resource` states: Loading/Failure toggle `resultLoading` / `resultLoadingError` (showing `errorString`); Success populates poster, title, author, rating, status, tag chips (clickable tags navigate to `global_to_navigation_mainpage`), synopsis (expand/collapse at `MAX_SYNO_LENGH = 300`), and builds the tab bar (Novel / Reviews / Related / Chapters) depending on `api.hasReviews`, related list, and whether it is a `StreamResponse` with chapters.

### Launching reading & downloading from the result page

The result page's primary button and overflow drive `ResultViewModel` actions, all gated on `hasLoaded` and serialized through `loadMutex` + `BookDownloader2.downloadInfoMutex`:

- **Read EPUB** (`resultDownloadGenerateEpub` → `readEpub()`): `addToHistory()` then `BookDownloader2.readEpub(loadId, progress, author, name, apiName, synopsis)`.
- **Quick stream / stream-read** (`resultQuickstream` → `streamRead(chapter?)`): `addToHistory()`, optionally persists the start chapter position keys (`EPUB_CURRENT_POSITION`, `EPUB_CURRENT_POSITION_CHAPTER`, `EPUB_CURRENT_POSITION_SCROLL_CHAR`) and marks it read, then `BookDownloader2.stream(load, apiName)`.
- **Download / pause / resume / stop / partial download** (`resultDownloadBtt` click & long-press → `doAction` → `download()`, `downloadOrPause()`, `pause()`, `stop()`, `downloadFrom(start)`): these inspect `BookDownloader2.downloadProgress[loadId].state` (`DownloadState.*`) and dispatch `BookDownloader2.addPendingAction(loadId, DownloadActionType.*)` or `BookDownloader2.download(load, context)`. `getActions()` computes the valid menu given the current `DownloadProgressState`.
- **Bookmark** (`resultBookmark` → `bookmark(state)`): writes `RESULT_BOOKMARK_STATE`, `updateBookmarkData()`, updates `readState`.
- **Share / open-in-browser** build `ACTION_SEND` / `ACTION_VIEW` intents from `loadUrl`.

Live download progress flows back via events: `ResultViewModel`'s `init` subscribes to `BookDownloader2.downloadProgressChanged` and `downloadRemoved`; `progressChanged((id, state))` updates `downloadState` only when `id == loadId`. The fragment observes `downloadState` to animate the two progress bars and set the button's label/icon per `DownloadState`.

Chapter list: `viewModel.chapters` (filtered & sorted by `orderChapters` using the static `filterChapterBy*` / `sortChapterBy` `PreferenceDelegate`s) feeds a `ChapterAdapter`; the chapters FAB opens a filter/sort `ChapterFilterPopupBinding` bottom sheet. Reviews are paged lazily (`loadMoreReviews`) on scroll-to-bottom.

## 6. The bottom-sheet preview popup (`MainActivity` + activity-scoped `ResultViewModel`)

`MainActivity` owns its own `ResultViewModel` via `by viewModels()` to power a quick metadata preview without a full navigation. Static entry points:

- `MainActivity.loadPreviewPage(searchResponse)` / `(DownloadDataLoaded)` / `(ResultCached)` → `mainActivity?.loadPopup(...)` → `viewModel.initState(...)` (cache overloads, no network for cached/download cards).

`MainActivity.onCreate` observes that view model:
- `loadResponse`: `null` → dismiss; `Loading` → show sheet with spinner; `Failure` → toast `error_loading_novel` + dismiss; `Success` → inflate/populate `BottomPreviewBinding` (poster, title, synopsis dialog, rating, status, chapter count). The **Read more / poster / more-info** buttons call `loadResult(d.url, viewModel.apiName)` then `hidePreviewPopupDialog()` — i.e. the preview escalates into a full `ResultFragment` via the §5 flow.
- `readState` updates the bookmark icon/label; `downloadState` toggles the delete/trash button.

The sheet is a `BottomSheetDialog` (`bottomPreviewPopup`) created lazily in `showPreviewPopupDialog()`; dismissing it calls `viewModel.clear()`.

## 7. Deep links & shared URLs (`MainActivity` intent handling)

`MainActivity.handleIntent(intent)` (called from `onCreate` and `onNewIntent`) handles externally-supplied URLs:

- **`Intent.ACTION_SEND`** (share-to-QuickNovel): tries, in order, the clip-data item's URI, the clip text, then `EXTRA_TEXT`, passing each to `loadResultFromUrl(...)` and returning on the first that succeeds.
- Otherwise it falls back to `intent.data` (a VIEW deep link) → `loadResultFromUrl(data)`.

`AppCompatActivity.loadResultFromUrl(url)`:
1. Iterates `apis`; if `url.contains(api.mainUrl)`, calls `loadResult(url, api.name)` and returns `true` — i.e. a shared novel URL from a supported site opens straight into the detail page.
2. Special case: `RedditProvider.getName(url)` — if it is a Reddit post, it builds an ad-hoc `QuickStreamData` (single `ChapterData`) via `createQuickStream(...)` and calls `openQuickStream(uri)` to stream it directly.
3. Returns `false` if nothing matched.

The `<intent-filter>`s that register these URL/SEND deep links live in `AndroidManifest.xml`; `MainActivity` is the handler.
